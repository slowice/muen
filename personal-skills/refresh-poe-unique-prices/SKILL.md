# 刷新传奇装备

重新取得当前数据，不把旧工作簿或 `/private/tmp` 缓存当作最新结果。默认生成 Standard 永久区粉尘页面当前能够枚举的完整传奇装备清单，并按粉尘价值降序排列，不设固定数量上限。

“完整”以本次刷新时 Standard 页面实际提供的全部分页数据为准。必须读取到最后一页，并用页面总数、实际提取行数和首尾记录交叉确认；不得把 Top 200、Top 400 或其他截断结果描述为完整清单。

## 默认产物

- 输出目录：`$HOME/.restx/temp/poe`
- 文件名：`poe_standard_unique_full_YYYY-MM-DD.xlsx`
- 主表只保留六列，顺序固定：`传奇名称`、`底材名称`、`粉尘价值`、`价格(C)`、`粉尘/C`、`传奇来源`
- `价格(C)` 的单位始终是 Chaos Orb；不要把 Divine 数值直接写入该列。
- `粉尘/C = 粉尘价值 ÷ 价格(C)`。价格缺失或为零时留空，不要伪造为零。

用户指定不同联盟、数量、阈值或输出位置时，以用户要求为准，并在结果中明确说明改变的口径。

## 数据流程

1. 打开并确认粉尘来源是 `https://poe-disenchant-tool.vercel.app/standard`，不能误用 `/allflame` 或页面当前残留的其他联盟状态。
2. 找到页面当前实际使用的数据请求或可验证的数据文件，获取传奇名称、底材名称和粉尘价值。不要仅依赖截图或可见首屏。
3. 从 poe.ninja 当前 Standard 页面或它当前实际加载的数据源取得价格。旧的 `/api/data/...` 端点可能返回 `not found`，不得因为历史脚本中存在就假定仍可使用。
4. 价格匹配至少同时使用传奇名称和底材名称，防止同名变体或错误底材串行。存在多个可比市场变体时采用保守的最低有效 Chaos 价格，并保留内部审计证据；无可靠匹配时留空并说明。
5. 遍历 Standard 粉尘页面的全部分页并提取所有条目。记录页面声明的总数、分页数、实际提取行数、第一条和最后一条；任一数量不一致时不得交付为完整清单。
6. 按粉尘价值数值降序排列完整清单。`4.2m` 等缩写必须先还原为整数，不能误写成 `420000`。
7. 使用 [references/unique-sources.csv](references/unique-sources.csv) 按 `传奇名称 + 底材名称` 精确补充 `传奇来源`。已有匹配直接复用静态结论，不要每次全量重查 Wiki；仅对新增、改名或底材不匹配的条目查询 PoE Wiki，确认后更新来源库。未知条目不得擅自归入普通掉落。
8. 创建或修改 `.xlsx` 时必须使用可用的 Spreadsheet skill，并遵守其生成、检查和渲染流程。主表之外保留 `来源审计` 表，至少包含传奇名称、底材名称、传奇来源、判定依据、Wiki 匹配方式和 Wiki 查询 URL。

详细字段口径见 [references/data-contract.md](references/data-contract.md)。

## 必做检查

- 确认数据联盟为 Standard 永久区，并在最终回复中写明数据日期。
- 确认已经到达最后一页，页面声明总数与实际提取行数一致；说明本次完整清单的实际条目数。
- 抽查粉尘榜第一名及至少五条跨数量级数据，确认 `k/m` 单位换算正确。
- 检查传奇名称与底材名称没有互换。
- 检查价格均为 Chaos 数值；Divine 报价必须先使用同期 Chaos/Divine 汇率换算。
- 检查每条记录均成功匹配静态来源库，且 `传奇来源` 只能是 `BOSS掉落`、`普通掉落`、`其它掉落`。
- 检查重复行、空名称、异常负数、排序错误和公式错误。
- 渲染并实际查看主表及所有辅助表，确认标题、列宽、数值格式和完整行数可用。
- 最终提供生成文件的绝对路径和可点击文件链接。

## 边界

- 此技能刷新的是传奇装备列表，不主动修改 FilterBlade 配置或底材显示建议。
- 不用底材平均价值替代单件传奇价值。
- 传奇来源采用稳定三分类：`BOSS掉落` 只指由明确 Boss 直接掉落；`普通掉落` 指常规世界掉落池；升级/合成、配方、宝箱、迷宫、仪式、劫盗、特殊机制或场景、赛季遗留及不可自然掉落等均归入 `其它掉落`。同时存在 Boss 与非 Boss 取得方式时归入 `其它掉落`。
- 不把 poe.ninja 价格描述为官方成交价；价格来源和不确定性必须清楚标注。
- 如果数据源结构变化或访问失败，先报告准确阻断点，不得沿用旧价格冒充刷新结果。
