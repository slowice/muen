# 总结最近一个问题

从当前总结请求向前识别最近一个完整问题弧，给出基于已有证据的复盘。

## 识别边界

1. 排除当前这条“请总结”的元请求，从它之前寻找最近的实质性用户目标。
2. 将围绕同一成功标准的追问、澄清、批准、实现和结果归入同一个问题弧；消息数量不决定问题数量。
3. 遇到更早且成功标准不同的独立目标时停止回溯。
4. 更早的问题仅在它是最近问题的必要因果背景时用一句话交代，不展开其调查和解决过程。

例如：先修复 Lite 会话分享，之后又询问如何在本地开启 Lite。最近问题是“本地开启 Lite”，分享问题最多作为测试动机出现。

## 证据与结论

- 优先依据该问题弧中的用户原话、已执行的工具结果、代码差异和验证结果。
- 只有在现有记录不足且只读核对成本很低时，才检查当前文件或状态；总结本身不重新实施问题。
- 明确区分已确认事实、合理推断和仍未解决的事项。上下文被压缩或证据缺失时，直接说明可恢复的边界，不补写不存在的过程。
- “难点”只记录真正影响判断或实现的障碍；普通操作步骤不包装成难点。

## 输出

默认使用以下四个标题，内容简洁但能独立读懂：

### 你问了什么

概括目标、关键约束和验收标准。

### 得到的结论

先给最终判断，再说明当前完成状态及必要的不确定性。

### 过程中有哪些难点

说明边界判断、信息不一致、技术限制或验证限制，以及它们为何重要。

### 怎么解决的

说明关键调查思路、选择的方案、实际改动或操作，以及支持结论的验证证据。按因果关系组织，不复述逐条聊天或命令流水账。
